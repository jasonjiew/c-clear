# C-Clear 商业化与授权机制（V2 F6 技术底座）

> 状态：**技术底座已完成，本期不设功能墙、不接支付**。
> 定位：开源核心全功能免费；Pro 为可选付费项（定价参考见 V2 计划 §4 F6）。

## 设计原则（合规红线）

1. **不加入任何联网 DRM**——许可证是 Ed25519 离线签名文件，验证全程本地完成
2. **不降级现有免费功能**——免费用户拥有 V1/V2 全部功能
3. **不加入推广弹窗**——差异化根基（对标"火绒式干净"）
4. **Pro 功能位（本期占位、免费开放）**：F3 每周自动清理（`autoclean`）、F1 云规则推送频率（`cloud-rules-fast`）

## 许可证格式

`license.dat`（JSON）：

```json
{
  "payload": {
    "name": "客户名",
    "licenseId": "CC-XXXX",
    "productId": "c-clear-pro",
    "features": ["autoclean", "cloud-rules-fast"],
    "issuedAtUtc": "2026-09-13T00:00:00Z",
    "expiresAtUtc": null
  },
  "signature": "<base64 的 Ed25519 签名>"
}
```

- 签名对象 = payload 的**紧凑 JSON 规范字节**（UTF8），Ed25519（RFC 8032）
- 验证公钥内嵌于 `Cclear.Core/Licensing/LicenseService.cs` 的 `PublicKeyHex`
- Ed25519 实现：.NET 8 无内置类型（.NET 10 才加入），故 `Ed25519Rfc8032.cs`
  提供零依赖的 RFC 8032 精简实现（BigInteger 版本），正确性由 RFC 官方测试
  向量保证（见 `tests/Cclear.Core.Tests/LicenseTests.cs`）
- 安装位置：`%APPDATA%\C-Clear\license.dat`

## 密钥管理与签发流程（项目方操作）

```bash
# 1. 生成密钥对（私钥线下保管，绝不提交仓库！）
dotnet run --project tools/LicenseTool -- keygen my-private-seed.hex
#    输出公钥 → 替换 LicenseService.PublicKeyHex 后重新发布应用

# 2. 编写订单信息 license.json
#    { "name": "张三", "licenseId": "CC-2026-0001",
#      "features": ["autoclean", "cloud-rules-fast"], "expiresAtUtc": null }

# 3. 签发
dotnet run --project tools/LicenseTool -- sign license.json my-private-seed.hex license.dat

# 4. 校验（可选）
dotnet run --project tools/LicenseTool -- verify license.dat
```

> 当前仓库内嵌的是**开发期密钥对**的公钥；正式对外销售前必须重新 keygen
> 并替换公钥，开发私钥（不在此仓库）作废。

## 用户激活流程

设置 → 关于 → 许可证 →「导入许可证」→ 选择 license.dat → 本地 Ed25519
验签 + 产品校验 + 有效期检查 → 通过后写入 `%APPDATA%\C-Clear\license.dat`。
