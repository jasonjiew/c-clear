## 1. 架构（定死，不摇摆）

```text
Cclear.sln
├─ src/Cclear.Core            类库：无 UI 依赖，全部可单测
│  ├─ Scanner/    IScanner 接口（引擎可替换——上一轮结论的落地）
│  │     ├─ ManagedTreeScanner   MVP：多线程 API 枚举，无需管理员
│  │     ├─ MftScanner           v1.1：FSCTL_ENUM_USN_DATA 直读 NTFS
│  │     └─ （预留）NativeScanner 逃生舱：Rust/C++ 引擎 P/Invoke
│  ├─ Rules/      规则模型 + JSON 规则包加载 + 匹配引擎
│  ├─ Analyzer/   扫描结果 × 规则 → CleanPlan（分类清单+预估）
│  ├─ Cleaner/    执行器：占用预检 → IFileOperation 回收站 →
│  │              失败跳过 → 真实释放统计 → JSONL 审计日志
│  │              （全局黑名单硬编码在此层，规则文件不可覆盖）
│  └─ Win32/      回收站/卷信息/服务启停/进程检测
├─ src/Cclear.App             WPF + MVVM（CommunityToolkit.Mvvm）
│  ├─ 总览页      C 盘仪表 + [一键体检]
│  ├─ 空间分析页  目录树 + 大文件 TopN + 扩展名统计
│  ├─ 清理清单页  分类勾选 → 确认 → 执行 → 实际释放报告
│  └─ 设置页      排除目录 / 永久删除开关 / 规则查看 / 日志
└─ tests/Cclear.Core.Tests    xunit（用自带断言，避免 FluentAssertions v8 商用授权坑）
```

数据流一条线：`Scan(C:) → Tree → 规则匹配 → CleanPlan 预览 → 用户确认 → Clean → FreedBytes + 日志`

**明确不做**（防过度设计）：注册表清理、内存优化、开机加速、常驻后台、驱动清理；重复文件/空目录放 W5；卸载放 v2。

## 2. 里程碑：W0 → W6

### W0 工程地基（半天）
- `git init`；`.gitignore`（VS 模板）；`LICENSE`（本项目选 **MIT**）；`Directory.Build.props`（`Nullable=enable`、`LangVersion=12`、`TreatWarningsAsErrors=true`）
- Solution：`src/Cclear.Core`、`src/Cclear.App`（WPF）、`tests/Cclear.Core.Tests`
- NuGet 基座：CommunityToolkit.Mvvm、Microsoft.Extensions.DependencyInjection/Hosting、Microsoft.Extensions.FileSystemGlobbing
- GitHub Actions CI：windows-latest，`dotnet build + test`，PR 门禁
- 冒烟：空 WPF 窗口跑起来

### W1 并行扫描器 + 目录树 UI（核心地基）
任务：
1. `FileTree`：struct 节点池 + 索引（非对象树），自底向上聚合大小与文件数
2. `ManagedTreeScanner`：
   - `EnumerationOptions { AttributesToSkip = ReparsePoint, IgnoreInaccessible = true }`
   - 分治/目录队列并行（CPU 核数上限），**reparse point/junction 不跟随**
   - 识别 OneDrive 占位（`FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`）：计入大小、永不触碰
   - 无权限目录汇总到 AccessDeniedList，不中断
   - `IProgress<ScanProgress>`（文件数/秒、当前目录）+ `CancellationToken`
3. App：虚拟化目录树（懒加载子节点）、按大小排序、进度条、取消
4. 测试：临时目录合成树、junction 不重复计、长路径（>260 字符）

**验收**：NVMe 全 C 盘 < 3 分钟；UI 不卡（异步）；junction 不重复计大小。
**参考**：dust / dua-cli 并行遍历思路（读源码）；WinDirStat 2.x 的 reparse/云文件行为作基准。

### W2 空间分析 + 体检框架
- 大文件 TopN（默认 >100MB 可调）、扩展名统计视图
- 规则模型 v0：`Category{ id, 名称, 安全级(SAFE/CAUTION/MANUAL/NEVER), 路径模板(环境变量展开+遍历所有用户), 文件模式, 最短年龄, 需要管理员, 前置条件 }`
- SAFE 第一批：`%TEMP%`>72h、`C:\Windows\Temp`、thumbcache/iconcache、`CrashDumps`、`WER\ReportQueue/Archive`、`D3DSCache`
- Analyzer 产出 CleanPlan：分类大小、文件数、安全级说明
- 总览页（C 盘仪表 + 一键体检）+ 清理清单页 v0

**验收**：体检对 %TEMP% 的估算与手选相符；规则 JSON 可热加载。
**参考**：BleachBit `cleaners/*.xml`（GPL——只取"哪些路径是垃圾"这一事实清单，用自己的 JSON 重新表达）；Storage Sense 默认参数（TEMP 72h）。

### W3 清理执行器（安全核心，本项目生命线）
- NuGet 引 **Vanara.Windows.Shell**（MIT）或 CsWin32：`IFileOperation`（`FOF_ALLOWUNDO`，默认进回收站）、`SHQueryRecycleBin`（按卷列大小）、`GetDiskFreeSpaceEx`
- `LockedFileDetector`：删除前独占打开/重命名测试 → 共享冲突即跳过并计数
- ServiceController：`wuauserv`/`bits` 停 → 清 `SoftwareDistribution\Download` → 启；失败即放弃该项
- 浏览器进程检测（chrome/msedge/firefox 运行中 → 跳过其缓存并提示）
- **全局黑名单硬编码**：`Windows\Installer`、`Package Cache`、`WinSxS`、`System Volume Information`、用户五大目录、OneDrive 根、pagefile/hiberfil/swapfile、DriverStore、Program Files（未命中规则时）
- JSONL 审计日志（路径/大小/时间/规则 id/结果）；释放量 = `GetDiskFreeSpaceEx` 前后差值
- UI：确认对话框（分类+明细+预计释放）、执行进度、结果页（实际释放/跳过清单）

**验收红线**：0 误删；回收站可恢复；占用文件 0 强删；每次删除可在日志回查。
**参考**：Vanara（MIT，NuGet 直接用）；BCU 的确认交互与警告文案（Apache-2.0）。

### W4 开发缓存专项（差异化卖点）+ 设置页
- 14 条开发缓存规则（每条注明"重建代价"+ 优先官方 CLI）：
  | 工具 | 路径/方式 | 官方命令优先 |
  |---|---|---|
  | npm | `%LOCALAPPDATA%\npm-cache` | `npm cache clean --force` |
  | pnpm | `%LOCALAPPDATA%\pnpm\store` | `pnpm store prune` |
  | yarn | `%LOCALAPPDATA%\Yarn\Cache` | `yarn cache clean` |
  | pip | `%LOCALAPPDATA%\pip\cache` | `pip cache purge` |
  | poetry/uv | 各自 cache 目录 | 各自命令 |
  | gradle | `~/.gradle/caches` | 无，直接删（CAUTION：重下依赖） |
  | maven | `~/.m2/repository` | 无（CAUTION，不动 settings.xml） |
  | nuget | `%USERPROFILE%\.nuget\packages` | `dotnet nuget locals all --clear` |
  | cargo | `~/.cargo/registry/cache` | 无 |
  | HuggingFace | `~/.cache/huggingface` | 无 |
  | Docker | —— | `docker system prune`（检测 Docker 运行中） |
  | IDEA | `%LOCALAPPDATA%\JetBrains\*\caches`、`log` | 无 |
  | VS Code | `%APPDATA%\Code\Cache`、`CachedData`、`Code Cache` | 无（检测运行中） |
- 设置页：排除目录、永久删除开关（二次确认）、规则查看、日志位置
- CAUTION/MANUAL 规则打磨（SoftwareDistribution、Windows.old 引导走系统磁盘清理、Logs 只报告）

**验收**：每条规则有虚拟目录单测；`pnpm store prune` 路径被优先调用而非硬删。

### W5 重复文件 + 空目录 + 边界测试
- DupFinder 三级漏斗：按大小分组 → 首尾 4KB 预哈希 → SHA-256 确认；保留策略（最旧/路径）UI；默认仅分析选定目录
- EmptyDirFinder：自底向上折叠，排除受保护目录
- 边界测试：长路径、多用户、中文/特殊字符路径、OneDrive 占位、标准用户权限、回收站交互、休眠中的杀软锁定

**验收**：10GB 样本重复检测 < 2 分钟（SSD）；空目录不误报系统特殊目录。
**参考**：**czkawka_core（MIT）**——首选：把 `czkawka_core` 作为 crate 编译成 cdylib 用 P/Invoke 调 duplicates/empty_folders 模块；备选：按其算法在 C# 重写（漏斗逻辑约 300 行）。

### W6 性能 + 打包 + 公开 beta
- MFT POC：`FSCTL_ENUM_USN_DATA` + `DeviceIoControl`，解析 USN_RECORD 流 → 按 ParentFileReference 建树；需管理员，失败自动回退 ManagedTreeScanner。目标：NTFS 全 C 盘 **秒级**
- 打包：`dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true`；应用图标；GitHub Release
- winget manifest 提交；README（截图 + 安全说明）
- 测试矩阵：Win10 21H2/22H2 + Win11 23H2/24H2 × 管理员/标准用户

**验收**：beta 可发布；全 C 盘扫描（MFT 路径）< 30 秒。

## 6. 安全红线（贯穿全程，每周末回归）

1. 只在规则命中集合内操作；扫描永远只读
2. junction/symlink/reparse 不跟随、不整体删除
3. 删除前占用预检，冲突即跳过
4. 默认回收站；永久删除需显式开启 + 二次确认
5. 文件年龄阈值（TEMP 类 >72h）
6. 浏览器/应用运行中跳过其缓存
7. OneDrive 占位文件永不触碰
8. 全量 JSONL 审计日志
9. 释放量报真实值（磁盘空闲差值）
10. 黑名单硬编码于 Cleaner 层，任何规则不可覆盖
